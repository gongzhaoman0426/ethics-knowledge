# 按伦理原文作答

先检索，再写文章。不把模型自己的伦理观写成他的话。脚本都在本 skill 的 `scripts/` 下，以 skill 目录为工作目录运行。

## 检索

1. 把问题拆成 2–3 个子问题（例：「怎样学好技术做好产品」→ 怎么学 / 技术本事是什么 / 产品怎么做），每个子问题想 3–5 个近义词，并判断「我与谁」的关系，对应 AGENTS.md 伦理树里的二级类。涉及的二级类都要查，不要只盯一个类；一个主题常横跨几个类（如学技术横跨 与能力、与技术、与受教者、与原则）。
2. `scripts/find.sh 词1 词2 …` 在全库按命中数排序候选；再查 `ethics/index.csv` 的标题（`path` 含大类/小类/文件名，另有 `title`、`votes`）。短词误伤时换更具体的短语。
3. 选 3–8 篇，用 `scripts/read.sh <相对路径…>` 读**完整正文**。不得用 head/截断；没读到结尾的文章不得引用。赞数只作并列时的参考。
4. 每篇读完，用一句话判断：它回答的是用户问的哪一部分？答的是邻近问题的（例：问怎么做产品，读到的是国产替代的市场机会），弃用。

## 作答

成文必须是**一篇连贯的，看不出来是在说库里文章的，但是处处有引用的文章**。用原文口吻写，直接对「你」说话，从头读到尾像他本人在答这一问。

- **开头第一句**就是他的原话（做成链接），直接回答问题；不写「说到底是一件事」之类模型自己的概括、论点或总纲。
- **只写连贯段落**。不用加粗小标题、不分点、不编号，段与段靠论证衔接。
- **相关性闸门**：每一段必须回答用户问的某一部分。原文答的是相邻问题的段落，宁可不写；整篇宁可短，不凑「全面」。
- 引用做成正文里的 markdown 链接，不要用代码引用块打断文章。链接文字必须是原文里**逐字出现**的句子或短语（不得凭记忆改写、不得合并两处），href 用仓库内相对路径：

  `[爱和被爱的能力](ethics/与友人/与恋人/1095057238-爱和被爱的能力.md)`

  路径含空格或括号时写成 `(<ethics/...>)`。几乎每句能指回原文的话都要挂链，不要一段只在段末丢一个总链。
- 多篇口径不同，用同一口气说完两边（「另一方面」「若问的是……」），不要点篇名、不要写「一篇说、另一篇说」。能织进同一条论证的主张就织；织会造出库里没有的新立场时，宁可少写一句。

## 交稿前自检（必做）

把成文存成临时文件（放 skill 目录的 `scripts/` 之外的 /tmp，不要留在仓库里），运行：

`python3 scripts/check_links.py /tmp/answer.md`

有 `[缺文件]` 或 `[非原文]` 的逐条修：改成原文逐字的短语，或删掉这句。全部通过才能把文章交给用户。再对照一遍：没有加粗小标题、第一句是原话、没有被闸门筛掉的段落。

## 禁止

- 「库里」「原文」「他写过」「几篇并排放着」「织进这篇」「出处如下」以及任何文献综述腔。
- 「原文 / 推论 / 出处」条目对照，先列要点再解释，文末篇目清单。
- 代码引用块（```start:end:path）当引用，除非用户明确要求。
- 用口吻补上模型自己的办法或常识。整题检索落空，只写一句没有，并列出已查关键词；局部没有的，直接不写，不要宣布「这里没有处方」。
- 整篇粘贴 `ethics/` 正文；不改这些文件，不擅自改分类；不主动布置课程或聚类任务。用户明确要今日一问时走 `daily-ethics`，不要在普通提问里顺手布置。
