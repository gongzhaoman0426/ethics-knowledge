# 按伦理原文作答

先检索，再写文章。不把模型自己的伦理观写成他的话。脚本都在本 skill 的 `scripts/` 下，以 skill 目录为工作目录运行。

## 检索

1. 把问题拆成 2–3 个子问题（例：「怎样学好技术做好产品」→ 怎么学 / 技术本事是什么 / 产品怎么做），每个子问题想 3–5 个近义词，并判断「我与谁」的关系，对应 AGENTS.md 伦理树里的二级类。涉及的二级类都要查，不要只盯一个类；一个主题常横跨几个类（如学技术横跨 与能力、与技术、与受教者、与原则）。
2. `scripts/find.sh 词1 词2 …` 在全库按命中数排序候选；再查 `ethics/index.csv` 的标题（`path` 含大类/小类/文件名，另有 `title`、`votes`）。短词误伤时换更具体的短语。
3. 选 3–8 篇，用 `scripts/read.sh <相对路径…>` 读**完整正文**。不得用 head/截断；没读到结尾的文章不得引用。赞数只作并列时的参考。
4. 每篇读完，用一句话判断：它回答的是用户问的哪一部分？答的是邻近问题的（例：问怎么做产品，读到的是国产替代的市场机会），弃用。

## 作答

回答固定由两部分组成：**正文**，和正文最下面的**引用列表**。

### 正文

成文必须是**一篇连贯的，看不出来是在说库里文章的文章**。用原文口吻写，直接对「你」说话，从头读到尾像他本人在答这一问。

- **开头第一句**就是他的原话，直接回答问题；不写「说到底是一件事」之类模型自己的概括、论点或总纲。
- **只写连贯段落**。不用加粗小标题、不分点、不编号，段与段靠论证衔接。**正文里不放链接。**
- **相关性闸门**：每一段必须回答用户问的某一部分。原文答的是相邻问题的段落，宁可不写；整篇宁可短，不凑「全面」。
- 主张尽量用原文的句子写，不凭记忆改写；每句话都要能在引用列表里的某一篇找到出处。
- 多篇口径不同，用同一口气说完两边（「另一方面」「若问的是……」），不要点篇名、不要写「一篇说、另一篇说」。能织进同一条论证的主张就织；织会造出库里没有的新立场时，宁可少写一句。

### 引用列表

正文结束后空一行，写一行 `引用：`，下面一行一篇，格式是「标签：链接」，链接是**知乎原文链接**：

```
引用：
- 工程师：https://www.zhihu.com/question/327471497/answer/716941677
- 实际产品：https://www.zhihu.com/question/666917640/answer/3632149835
```

- **标签**取该篇 frontmatter 的 `tag`；没有 `tag` 就用 `title`。
- **链接**取该篇 frontmatter 的 `url`，原样照抄。`scripts/read.sh` 输出每篇时会把标签和链接印在篇首，直接抄，不要自己拼。
- 只列正文**真正用到**的篇目，一篇一行，不重复，不列只是读过但没用的。顺序按正文里首次用到的先后。

## 交稿前自检（必做）

把整篇回答（正文 + 引用列表）存成临时文件（放 /tmp，不要留在仓库里），运行：

`python3 scripts/check_links.py /tmp/answer.md`

脚本会检查：引用列表每条链接是否对应库里的一篇、标签是否等于该篇的 `tag`/`title`、正文有没有链接/标题/加粗；并用「连续 8 个字与引用篇目重合」检查正文每句话有没有出处，列出没有出处的句子和没被正文用到的引用。有 `[错误]` 必须修；`[无出处]` 的句子逐句核对，要么改成原文的说法，要么删掉。通过后才能交稿。

## 禁止

- 「库里」「原文」「他写过」「几篇并排放着」「织进这篇」「出处如下」以及任何文献综述腔。
- 「原文 / 推论 / 出处」条目对照，先列要点再解释，「出处如下」之类的引子。文末只允许有上面规定的 `引用：` 列表，不要有别的清单。
- 代码引用块（```start:end:path）当引用，除非用户明确要求；在正文里夹 markdown 链接。
- 用口吻补上模型自己的办法或常识。整题检索落空，只写一句没有，并列出已查关键词；局部没有的，直接不写，不要宣布「这里没有处方」。
- 整篇粘贴 `ethics/` 正文；不改这些文件，不擅自改分类；不主动布置课程或聚类任务。用户明确要今日一问时走 `daily-ethics`，不要在普通提问里顺手布置。
